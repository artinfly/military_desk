# Перенос военно-учётного стола

## Функции старой программы

| Старая программа | Новое приложение |
|---|---|
| Главное окно и фильтры | Учётные карточки: ФИО, табельный номер, работающие/уволенные, ВУС, вид учёта, цех, военкомат, локальные точки, офицеры, бронь, СВО |
| Карточка работника | Личные сведения, документы, адреса, родственники, образование, назначения, дополнительные атрибуты |
| Воинский учёт | Документ, звание, ВУС, категории запаса и годности, состав, группа учёта, мобпредписание, бронирование, история военкоматов |
| Отчёт по фильтру | Excel из списка карточек с теми же условиями отбора |
| Численность, ВУС, призывники | Раздел «Отчёты» |
| Форма к распоряжению | Основная форма и оба приложения в одной книге Excel |
| Принятые и спец. уволенные | Отчёты с периодом |
| Список пребывающих в запасе для сверки | Все 18 колонок, включая ИНН, место выдачи документа, военкомат и родственников; одна строка на человека |
| Неучтённые | Отдельный отчёт по работающим без воинских сведений либо без вида учёта и примечания |
| Смена группы учёта | «Операции», только для незабронированных |
| Бронирование и разбронирование по файлу | «Операции», Excel со СНИЛС в первой колонке со второй строки; действуют только на работающих |
| Обновление спец. уволенных | «Операции» и после кадровой загрузки; повторный запуск не дублирует записи |
| Справка одному сотруднику | Кнопка в карточке работающего забронированного сотрудника |
| Справки по цехам | «Отчёты → Справки о бронировании»; печать и сохранение в PDF |
| Редактор справки | Текст, организация и поля подстановки; доступ администратора учёта, проверка одновременных изменений |
| Загрузка vus.csv | «Обмен данными»: проверка с откатом и применение, журнал; также команда `sync_hr` |
| Загрузка vus_ext.csv | Сопоставление по табельному номеру, ОКПДТР и категория; строки без кода учитываются отдельно |
| proff.dbf | ZIP с обработанным proff.dbf, отклонёнными строками, итогом |
| KADR_EDAY.dbf | ZIP с kadr940.dbf, отклонёнными строками, повторными табельными номерами и неизвестными кодами |
| spr.dbf | Выгрузка используемых кадровых кодов с назначенной строкой NS; редактирование NS в разделе обмена |
| Копирование базы | Команда `backup_database`, PostgreSQL `pg_dump`, существующая копия не заменяется |
| Справочники | Скрыты из рабочего меню; выбор больших справочников — отдельное окно с поиском и страницами |

Пустые и неиспользуемые в исходной базе разделы не возвращаются в рабочий интерфейс.
Таблицы родственников с нулём строк, служебные настройки старой программы и старые
учётные записи не подменяют роли и вход Django. Используемый справочник первого
отдела `spr` переносится вместе с основной базой.

## Начальный перенос

Сначала настройте **отдельную пустую PostgreSQL-базу** в `.env` и выполните миграции.
Исходная база и SQL-файл используются только для чтения. Текстовый `.sql` разбирается
как данные COPY; SQL из него не исполняется. Архив `.dump` можно восстановить в
отдельную исходную базу через `pg_restore` и читать её командой `import_legacy --host`.

```powershell
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py import_legacy --dump "D:\Перенос\stol.sql" --dry-run
.venv\Scripts\python.exe manage.py import_legacy --dump "D:\Перенос\stol.sql"
.venv\Scripts\python.exe manage.py audit_data
```

Команда откажется переносить карточки в уже заполненную базу. `--replace` удаляет
имеющиеся карточки и разделы, поэтому для обычного обновления используется `sync_hr`.
При ошибке начальный перенос откатывается целиком. Пробный режим тоже не сохраняет данные.

## Последующие кадровые обновления

`vus.csv` — TSV с исходным порядком 286 колонок и служебной первой строкой,
Windows-1251 или UTF-8. Коды городов, улиц и домов могут быть UUID. Повторы исходных
записей обрабатываются в порядке файла: последнее значение имеет приоритет, количество
таких замен показывается в замечаниях. Разные ФИО/даты рождения/табельные номера при
одном идентификаторе карточки считаются ошибкой и отменяют загрузку.

Повторный импорт сохраняет связи с исходными идентификаторами, обновляет разделы,
не удаляет отсутствующих в файле людей. Ручная бронь, приказ и данные воинского документа
забронированного сохраняются. После разбронирования кадровая загрузка сохраняет общий учёт.
Телефон, почта и другие поля, которых нет в выгрузке, не очищаются.

Для больших файлов удобнее команда без ограничения времени веб-запроса:

```powershell
.venv\Scripts\python.exe manage.py sync_hr --file "D:\Перенос\vus.csv" --extended "D:\Перенос\vus_ext.csv" --user <логин-оператора> --dry-run
.venv\Scripts\python.exe manage.py sync_hr --file "D:\Перенос\vus.csv" --extended "D:\Перенос\vus_ext.csv" --user <логин-оператора>
```

Оба файла сначала проверяются; применение идёт одной транзакцией. Крупные веб-загрузки
требуют достаточного тайм-аута сервера и лимита тела запроса не меньше размера файла.
Максимальный размер файла в приложении — 200 МБ. В журнале хранятся количества,
пользователь и контрольная сумма; сами файлы не сохраняются.

## DBF и справки

Исходные DBF не изменяются. В выходных файлах сохраняются исходная структура и байты
неизменяемых полей. Проверяются коды, признаки и категории; KADR_EDAY очищается от
повторных табельных номеров. SPECUH соответствует X4 → 2, R7 → 1, H9 → 3 только
для военнообязанных. У выходного SPECUH тоже проверяется SOSTAV. Неизвестные ОКПДТР
попадают в отдельный CSV, а не получают произвольную строку NS.

Встроенный текст справки — редактируемый макет. До выдачи документов внесите утверждённый
текст, организацию и реквизиты. Поля `{{ФИО}}`, `{{ПриказНомер}}` и другие доступны в редакторе;
код и HTML из текста не исполняются. Печать доступна в браузере с сохранением в PDF.

## Резервная копия и проверки

```powershell
.venv\Scripts\python.exe manage.py backup_database "D:\Копии\military-desk.dump"
.venv\Scripts\python.exe manage.py backup_database "D:\Копии\military-desk.json.gz" --format json
.venv\Scripts\python.exe manage.py test
```

Формат `json` работает без `pg_dump`: сохраняет данные приложения, роли и пользователей
в согласованном снимке, без активных сессий. Для восстановления разверните ту же версию
приложения, выполните миграции в пустой базе и `manage.py loaddata <копия.json.gz>`.
Формат PostgreSQL — полная копия базы для `pg_restore`.

Для проверки настоящих локальных материалов в **тестовой** базе задайте переменные
`MILITARY_LEGACY_DUMP` (путь к `.sql`) и `MILITARY_LEGACY_MATERIALS` (каталог исходников
и архивов старого приложения), затем запустите `manage.py test apps.legacy.tests_materials`.
Проверяются начальный перенос, обновление, повтор без дублей и обработка DBF. Материалы,
копии баз, секреты, персональные данные и результаты проверок не входят в Git.
